## 2. Introduction

The Route Finding Problem is a classic search problem in artificial intelligence where an agent must find optimal paths from an origin node to one or more destination nodes in a graph. This problem is fundamental to many real-world applications such as GPS navigation, network routing, and robot motion planning.

### Problem Description

In our implementation, the problem is represented as a directed weighted graph with:
- A set of nodes with 2D coordinates
- A set of directed edges with associated costs
- A designated origin node
- One or more destination nodes

The objective is to find a path from the origin to any destination node that minimizes the total cost.

### Graph and Tree Concepts

While the problem is defined on a graph, the search algorithms operate by constructing a search tree:
- **Graph**: A set of nodes connected by edges, where edges may form cycles
- **Tree**: A hierarchical structure where each node (except the root) has exactly one parent, and there are no cycles
- **Search Tree**: A tree constructed during search, where nodes represent states and edges represent actions

### Implemented Algorithms

We have implemented six search algorithms to solve this problem:

**Uninformed Search Algorithms**:
1. **Depth-First Search (DFS)**: Explores as far as possible along each branch before backtracking
2. **Breadth-First Search (BFS)**: Explores all nodes at the present depth before moving to nodes at the next depth level
3. **Iterative Deepening Depth-First Search (IDDFS)**: Our CUS1 algorithm, combines advantages of DFS and BFS by performing DFS with increasing depth limits

**Informed Search Algorithms**:
1. **Greedy Best-First Search (GBFS)**: Uses a heuristic to select the node that appears closest to the goal
2. **A* Search (AS)**: Combines the cost so far with a heuristic estimate of the remaining cost
3. **Bidirectional Search**: Our CUS2 algorithm, searches simultaneously from both origin and destination

## 5. Insights

Our testing revealed several interesting insights about the performance and behavior of different search algorithms:

### Node Expansion and Efficiency

1. **Uninformed vs. Informed Search**: 
   - In simple graphs with uniform costs, uninformed methods like DFS and BFS often expand fewer nodes
   - In complex graphs with varying costs, informed methods like GBFS and A* are more efficient
   - For example, in heuristic_test.txt, A* found the optimal path (1-3-5-6) with cost 25, while DFS found a suboptimal path (1-2-4-6) with cost 32

2. **Node Creation**:
   - DFS consistently created the fewest nodes across most test cases
   - IDDFS created significantly more nodes due to repeated exploration at different depth limits
   - Bidirectional search created more nodes but has the potential to be faster on very large graphs

### Path Optimality

1. **Path Quality**:
   - A* consistently found the optimal (lowest cost) paths
   - GBFS sometimes found suboptimal paths due to its focus solely on the heuristic
   - DFS and BFS found optimal paths in simple cases but not consistently in complex cases
   - For example, in heuristic_comparison.txt, A* found path (1-5-4) with cost 14, while DFS found (1-2-4) with cost 20

2. **Path Selection**:
   - When multiple paths of equal cost exist, the algorithms' choices reveal their biases:
   - DFS preferred deeper paths
   - BFS preferred shallower paths
   - GBFS and A* preferred paths that appeared closer to the goal based on the heuristic

### Time Performance

The execution times for all algorithms were very fast on our test cases, typically less than 0.0001 seconds. For larger, real-world graphs, we would expect to see more significant differences. The theoretical time complexities of the algorithms are:

- **DFS**: O(b^d) where b is the branching factor and d is the depth of the goal
- **BFS**: O(b^d) where d is the depth of the goal
- **GBFS**: O(b^d) but often much better in practice
- **A***: O(b^d) but optimally efficient among admissible algorithms
- **IDDFS**: O(b^d) where d is the depth of the goal
- **Bidirectional**: O(b^(d/2)) theoretically, but implementation-dependent

## 6. Research: Visiting All Destination Nodes with Shortest Path

As part of our research, we explored how to modify our program to find the shortest path that visits ALL destination nodes, rather than just reaching any destination node. This transforms the problem into a variant of the Traveling Salesman Problem (TSP) with a fixed starting point.

### Challenges

1. **Problem Complexity**: The TSP is NP-hard, meaning that finding an optimal solution for large graphs is computationally expensive
2. **Path Ordering**: Determining the optimal order to visit destinations is combinatorial
3. **Path Finding Between Points**: Each segment between consecutive destinations requires a separate search
4. **Integration with Existing Code**: Adapting our search algorithms to solve this multi-destination problem

### Our Solution

We implemented a solution using a two-level approach:

1. **Outer Level**: Find the optimal order to visit all destinations
   - For a small number of destinations, use brute force to check all permutations
   - For larger sets, use a nearest neighbor heuristic

2. **Inner Level**: Find the optimal path between each pair of consecutive points
   - Use A* search as it consistently finds optimal paths
   - Cache results to avoid redundant searches

```python
def visit_all_destinations(problem):
    """
    Find shortest path visiting all destinations, starting from origin.
    """
    # If only one destination, use regular A* search
    if len(problem.destinations) == 1:
        return astar(problem)
    
    # Step 1: Precompute optimal paths between all node pairs
    paths = {}  # Dictionary to store paths: (start, end) -> (cost, path)
    
    # Start with origin to all destinations
    for dest in problem.destinations:
        temp_problem = copy.deepcopy(problem)
        temp_problem.destinations = [dest]
        result = astar(temp_problem)
        if result:
            goal, node_count, path_string = result
            path = path_string.split()
            paths[(problem.origin, dest)] = (
                compute_path_cost(problem, path), 
                path
            )
    
    # Between all pairs of destinations
    for start in problem.destinations:
        for end in problem.destinations:
            if start != end:
                temp_problem = copy.deepcopy(problem)
                temp_problem.origin = start
                temp_problem.destinations = [end]
                result = astar(temp_problem)
                if result:
                    goal, node_count, path_string = result
                    path = path_string.split()
                    paths[(start, end)] = (
                        compute_path_cost(problem, path), 
                        path
                    )
    
    # Step 2: Find best order of destinations
    best_order = None
    best_cost = float('inf')
    
    # For small number of destinations, brute force is feasible
    if len(problem.destinations) <= 8:
        # Try all permutations
        for perm in itertools.permutations(problem.destinations):
            order = [problem.origin] + list(perm)
            cost = 0
            valid_path = True
            
            for i in range(len(order) - 1):
                if (order[i], order[i + 1]) in paths:
                    cost += paths[(order[i], order[i + 1])][0]
                else:
                    valid_path = False
                    break
            
            if valid_path and cost < best_cost:
                best_cost = cost
                best_order = list(perm)
    else:
        # Use nearest neighbor heuristic for larger sets
        remaining = set(problem.destinations)
        current = problem.origin
        order = []
        
        while remaining:
            next_dest = min(
                remaining, 
                key=lambda x: paths.get((current, x), (float('inf'), []))[0]
            )
            order.append(next_dest)
            remaining.remove(next_dest)
            current = next_dest
        
        best_order = order
    
    # Step 3: Construct the complete path
    complete_path = [str(problem.origin)]
    node_count = sum(paths[(problem.origin, best_order[0])][0])
    
    for i in range(len(best_order)):
        start = problem.origin if i == 0 else best_order[i-1]
        end = best_order[i]
        
        # Skip first node as it's already included
        segment_path = paths[(start, end)][1][1:]
        complete_path.extend(segment_path)
    
    path_string = " ".join(complete_path)
    return best_order[-1], node_count, path_string
```

### Results and Insights

1. **Performance**: The solution works well for problems with up to 8 destinations, but becomes computationally expensive for larger sets
2. **Path Quality**: The paths found are optimal for small sets and near-optimal for larger sets
3. **Comparison with Single-Goal Search**: Visiting all destinations requires significantly more computation but ensures comprehensive coverage
4. **Application**: This approach is useful for scenarios like delivery routing, inspection tasks, or resource collection

## 7. Conclusion

After implementing and testing six different search algorithms for the Route Finding Problem, we can draw several conclusions about their relative performance and suitability:

### Algorithm Selection Guidelines

1. **For Simple Graphs with Uniform Costs**:
   - BFS is optimal and efficient when all edge costs are equal
   - DFS is efficient for deep graphs with limited branching

2. **For Complex Graphs with Varying Costs**:
   - A* consistently finds optimal paths and is generally the best choice
   - GBFS provides a good balance of efficiency and near-optimality

3. **For Special Cases**:
   - IDDFS is useful when memory is limited and the solution depth is unknown
   - Bidirectional search can be extremely efficient for very large graphs

### Performance Improvements

Several improvements could enhance the performance of our implementation:

1. **Memory Optimization**:
   - Use more efficient data structures for the frontier and explored sets
   - Implement iterative rather than recursive versions of algorithms to avoid stack overflow

2. **Heuristic Enhancements**:
   - Develop problem-specific heuristics beyond simple Euclidean distance
   - Use adaptive heuristics that adjust based on graph properties

3. **Parallelization**:
   - Implement parallel versions of search algorithms for large graphs
   - Explore multiple promising paths simultaneously

4. **Visualization**:
   - Add graphical visualization of the search process
   - Display the final path on a graph representation

### Final Recommendation

For the Route Finding Problem as defined in this assignment, A* search provides the best balance of efficiency and optimality. Its ability to find minimum-cost paths while exploring relatively few nodes makes it the preferred algorithm for most scenarios. For very large graphs, bidirectional search or other memory-efficient variants may be necessary.
